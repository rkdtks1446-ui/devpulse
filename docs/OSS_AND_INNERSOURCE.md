# OSS 라이선스 비교 분석 및 Inner Source 도입 로드맵

## 1. 주요 오픈소스 라이선스 비교 분석
DevPulse는 대학 팀 프로젝트 및 오픈소스 생태계에서 누구나 제약 없이 포크(Fork)·수정·재배포할 수 있도록 **MIT License**를 채택했습니다.

| 비교 항목 | MIT License (채택) | Apache License 2.0 | GNU GPL v3.0 |
| :--- | :--- | :--- | :--- |
| **상업적 이용 및 수정** | 허용 | 허용 | 허용 |
| **배포 및 사적 이용** | 허용 | 허용 | 허용 |
| **특허권 명시적 허여** | 미명시 | **명시적 허여 (Patent Grant)** | 명시적 허여 |
| **소스코드 공개 의무** | **없음 (Permissive)** | **없음 (Permissive)** | **있음 (Strong Copyleft)** |
| **라이선스 및 저작권 고지** | 필수 | 필수 (+ 변경 내역 명시) | 필수 |
| **적합한 프로젝트 유형** | 경량 개발 도구, 교육·협업 유틸리티 | 특허 분쟁 보호가 필요한 기업용 프레임워크 | 파생 저작물 전체를 오픈소스로 강제할 때 |

### MIT License 선정 근거
1. **낮은 도입 장벽**: 소스코드 공개 의무(Copyleft)가 없어 학우들이나 다른 팀이 DevPulse의 DORA 수집 스크립트와 PR 분석기를 각자 프로젝트에 자유롭게 통합할 수 있습니다.
2. **명확하고 간결한 조항**: 저작권 및 라이선스 고지만 유지하면 자유로운 활용이 가능해 외부 기여자의 온보딩 비용이 낮습니다.

## 2. 조직 내 Inner Source 도입 4단계 로드맵
오픈소스 협업 문화(투명한 이슈 관리, PR 기반 코드 리뷰, 자동화된 CI 검증)를 학과/조직 내부 개발 환경에 정착시키기 위한 4단계 로드맵입니다.

| 단계 | 핵심 목표 | 주요 실행 과제 | 측정 지표 (KPI) |
| :--- | :--- | :--- | :--- |
| **1단계: 표준화 (Standardization)** | 저장소 구조 통일 및 가시성 확보 | • `README`, `CONTRIBUTING`, `CODEOWNERS`, `LICENSE` 템플릿 배포<br>• `main` 브랜치 보호 및 Conventional Commits 적용 | 표준 문서 적용 저장소 비율 100% |
| **2단계: 파일럿 (Pilot)** | 공통 모듈 중심의 타 팀 기여 시범 운영 | • 공통 유틸리티/CI 액션 저장소 2개 선정<br>• `[MUST]` / `[SHOULD]` 태그 기반 상호 코드 리뷰 운영 | 외부(타 팀) 기여 PR 건수 및 리뷰 응답 시간(SLA) |
| **3단계: 거버넌스 (Governance)** | 품질 자동 검증 및 리뷰어 체계 정착 | • GitHub Actions Matrix 테스트 및 자동 린트 게이트 구축<br>• 모듈별 Trusted Committer(핵심 리뷰어) 지정 | CI 통과율 및 평균 PR 병합 리드 타임 |
| **4단계: 확산 (Scale-out)** | 데이터 기반 회고 및 전사 문화 정착 | • DORA 4대 지표 대시보드 정례 리뷰<br>• 우수 코드 리뷰어 및 기여자 포상 프로그램 운영 | 배포 빈도(DF) 향상 및 변경 실패율(CFR) 15% 이하 유지 |
